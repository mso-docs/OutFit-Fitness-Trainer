# Health data and trainer prototype

OutFit now has trainer chat, optional height/weight, and an imported-activity timeline. No live provider authorization or background sync is implemented.

## Current behavior

- Settings accepts centimetres/kilograms or inches/pounds. Values are stored in the local profile as centimetres/kilograms, included in JSON export, and removed by deleting local data. Blank values clear a measurement. Existing profiles default to null; profile editing preserves measurements. These are latest values, not a weight-history chart, and do not modify exercise policy.
- Trainer chat uses the selected Ollama model. It receives the conversation, accepted plan, catalog instructions, goal, experience, and aggregate activity totals. It excludes body measurements and raw log/check-in notes automatically. Users can still disclose information by typing it themselves. Messages are not saved in SQLite or browser storage; leaving the Trainer screen clears them. The model server receives readable messages: this is not end-to-end encrypted messaging or a guarantee that the inference server retains nothing.
- Chat has strict input limits, bounded model calls, concurrency/rate controls, Markdown rendering with raw HTML and embedded images disabled, an offline notice, and server-side gates for existing safety flags and recognized symptom/medical terms. These gates are conservative prototype controls, not a complete medical-language classifier. Model advice requires review; there is no automatic plan mutation. Plan changes still use the independently validated draft/acceptance flow.
- Health data accepts normalized JSON file imports. Records are keyed by source/external ID; newer modification timestamps replace older versions. Tombstones prevent older files resurrecting deleted activities. Imports are shown with provider source, file-import label, date in the profile timezone, duration and optional distance. Up to 100 records/file, 32 KiB/request and 2,000 stored records. Export includes imports and tombstones; local-data deletion removes them.
- Imported activity is deliberately separate from manual progress and trainer totals until identity matching/reconciliation with logged workouts is implemented. Missing steps, sleep or heart-rate data is displayed as unavailable, never fabricated as zero.

## Live connections

| Provider       | Implementation needed                                                                                                                                                                                                                                                                                 | Display after consent/sync                                                                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Strava         | Register an API application, OAuth authorization with state validation, narrowly scoped activity permission, server-side token storage/refresh, paginated activity fetch and updates/deletions. Protect token storage, avoid embedding secrets in browser bundles, and support disconnect/revocation. | Normalized activity timeline; source badge, last successful sync, permission/expired-token errors.                                                                         |
| Apple Health   | An iPhone companion with HealthKit capability and per-type authorization reads permitted records and uploads a minimal normalized batch to the authenticated OutFit API. This browser app cannot directly query HealthKit.                                                                            | Permitted workouts; optionally steps/sleep/heart rate after separate data schemas and permission requests. Read denial must not be presented as a confirmed empty dataset. |
| Health Connect | An Android companion checks availability, declares/requests per-type permissions, reads records and syncs changes/deletions. Handle history permission limits and revocation.                                                                                                                         | The same normalized timeline, plus separate aggregates for supported steps/sleep types.                                                                                    |
| Garmin         | Confirm provider API access/approval and contract requirements before implementing an adapter.                                                                                                                                                                                                        | Only the metrics actually available through the approved integration.                                                                                                      |

Strava is the smallest next step for the existing web app. Apple/Android health stores require a phone app or native bridge; an OAuth button alone cannot connect them.

All providers should normalize timestamps, units, source timezone, external IDs, modifications and deletions before storage. Cross-source overlap (e.g. one Strava workout also read from a phone health store) needs a deduplication/confirmation rule before combining totals. Imported workouts should be linked explicitly to plan sessions before counting planned adherence. Connection state, permission scope and last-sync timestamps must be real provider results, never hard-coded success labels.
